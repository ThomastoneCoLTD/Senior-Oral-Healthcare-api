# 대구체인 운영 설정 대조

사용자 요청에 따라 SOH API와 SOH_DID의 체인 ID, 대구체인 호출용 인증 토큰, 관리자 지갑 설정을 읽기 전용으로 대조했습니다. 토큰 전송·회수·발행, 회원 및 지갑 데이터 변경, 환경변수 변경, 재시작과 배포는 수행하지 않았습니다.

## 기준과 확인 방법

- 조사일: 2026-10-06, AWS 계정 `160885266674`, `ap-northeast-2` 운영 환경.
- 로컬 SOH API 기준 커밋: `cf5bb84c`, `prod`. 로컬 변경의 배포 여부와 별도로 실행 서버를 조회했습니다.
- SOH API: `soh-api-prod-asg`의 `i-0ffdc33b565fbdd49`, 실행 Java 프로세스 PID `10529`, `/var/www/soh-api/app.jar`, 활성 프로필 `prod`.
- SOH_DID: `i-0ec6bbc8327248619`, 기존 SSH 경로로 조회. 실행 Gunicorn 프로세스 PID `987080`, `987096`, `987097`; 소스 `/opt/soh-did/current/myapp/utils.py`.
- SOH API는 SSM으로 실행 프로세스 환경변수와 배포 JAR의 application YAML을 조회하여 설정을 해석했습니다. 발견한 작업 디렉터리·config 디렉터리의 외부 application YAML은 없었고, 조회한 custom config location/import 설정도 없었습니다. 실행 중 Spring Bean을 직접 조회한 것은 아닙니다.
- SOH_DID는 실행 프로세스 환경변수와 운영 소스의 설정 바인딩을 대조했습니다. 비교 대상 5개 설정은 모두 프로세스 환경에 있었으며, 3개 Gunicorn 프로세스의 결과도 일치했습니다. utils.py에는 load_dotenv 호출이 없었습니다.
- 인증 토큰·지갑 주소·개인키는 서버에서 임시 난수를 사용하는 HMAC을 계산해 대조했습니다. 실제 비밀값과 비교용 해시는 이 문서에 기록하지 않았습니다. 운영 자격증명을 파일로 내려받거나 다른 서버의 설정에 복사하지 않았습니다.

SOH API의 DID·토큰 중계 주소는 모두 `http://43.201.125.82`로, 조회한 SOH_DID 서버를 가리킵니다.

`DAEGU_CHAIN_APP_KEY`와 SOH_DID의 `DCHAIN_API_TOKEN`은 서로 다릅니다. APP_KEY는 중계 요청에 쓰이는 앱 키이고 직접 대구체인 호출용 TOKEN과 구분되는 설정입니다. 이 차이를 인증 토큰 불일치로 해석하지 않습니다. 이번 조회에서는 앱 키 검증이나 대구체인의 인증 토큰 유효성·권한을 시험하지 않았습니다.

## 해석과 다음 확인

관리자 주소와 서명 키 설정은 두 서버에서 동일합니다. 따라서 설정 기준으로는 같은 관리자 지갑을 사용하며, 체인 ID만 다릅니다. 관리자 토큰 잔액·토큰 계약의 소유권과 해당 인증 토큰의 전송 권한은 이 비교만으로 보장되지 않습니다.

`dchain`과 `minic`이 실제로 서로 다른 네트워크인지, 동일한 네트워크의 별칭인지는 확인하지 않았습니다. 이 차이가 기존 전송 실패의 원인이라고 단정하지 않습니다. 대구체인 측의 체인 ID 규칙 및 기존 토큰 계약·거래가 속한 체인을 확인하기 전에는 어느 한쪽 값으로 일괄 변경하지 않습니다.

직접 지급·회수 전환 전에 체인 ID의 의미를 먼저 확인하고, 현재 계약 주소와 거래 증명 조회에 사용하는 체인이 일관되는지 검증해야 합니다. 기존 중계 지급·회수와 DID 발급은 유지합니다. 재전송이나 지갑 재생성은 수행하지 않습니다.
